### Autofix Applied
- 🟡 **Nested `<main>` inside `SidebarInset`** — `SidebarInset` renders as `<main>`; wrapping page content in another `<main>` is invalid HTML. Changed inner `<main>` to `<div>` (safe_auto — no behavior change, pure HTML validity fix).

### Minor Findings

🟡 **localStorage theme migration** — `STORAGE_KEY_THEME = 'cli-proxy-theme'` persists theme choice. Users with stored `'auto'` or `'white'` will have Zustand hydrate an invalid `Theme` value at runtime. `applyTheme('auto')` won't match `'dark'` so `.dark` class is not applied — user silently falls to light theme. Acceptable per spec ("remove auto and white"), but no migration guard or reset logic. No action needed for Phase 3; if desired, Phase 5 can add a migration to `useThemeStore.initializeTheme`.

💡 **NavLink `active` class on root route** — `NavLink to="/"` without `end` prop will add CSS class `active` to the `<a>` element on every route (all paths start with `/`). This doesn't affect sidebar `data-active` state (correctly controlled by `isItemActive`), but the NavLink default `active` class is present globally. No visible styling impact since legacy `.nav-item.active` SCSS selectors don't match bare `active` on `<a>`. Advisory — no fix needed now; Phase 4 can clean up when rebuilding pages.
